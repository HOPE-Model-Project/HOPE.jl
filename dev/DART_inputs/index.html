DART Input Data

A file-backed DART case follows the same top-level contract as GTEP and PCM:

case/
├── Settings/
│   ├── HOPE_model_settings.yml
│   └── <solver>_settings.yml
├── <DataCase>/
├── manifest.yml
├── stable_ids.csv
└── output/

model_mode: DART selects the DART loader. The DataCase value identifies the input directory, while manifest.yml pins the expected files and SHA-256 hashes. stable_ids.csv assigns durable generator, storage, bus, and branch identifiers independently of source-file labels.

Installed-system files

DART reuses the normal installed-system CSVs:

FileDART use
busdata.csvBus identity, zone, and peak load
branchdata.csvFixed network topology, reactance, and directional ratings
gendata.csvInstalled generator capability, cost, commitment, flexibility, and reserves
storagedata.csvInstalled storage energy, power, efficiency, cost, and reserves
single_parameter.csvVOLL, reserve requirements, and reserve response times
load_timeseries_regional.csvHourly day-ahead load factors
wind_timeseries_regional.csvHourly day-ahead wind availability
solar_timeseries_regional.csvHourly day-ahead solar availability

The converter validates row counts, stable-ID coverage, bus references, calendar ordering, finite values, and network connectivity before model construction. The current DART network formulation requires symmetric normal ratings and a lossless nodal PTDF representation.

Generator DART columns

DART-specific static generator attributes live directly in gendata.csv. They are optional for generic installed-system conversion and default conservatively, but a full DART case should define them explicitly:

ColumnMeaning
quick_start_eligibleWhether an offline unit may provide NSPIN
quick_start_time_minutesTime required to qualify as quick-start
no_load_cost_per_hourHourly committed no-load cost
shutdown_costCost of a shutdown transition
startup_limit_fractionStartup output limit as a fraction of Pmax
shutdown_limit_fractionShutdown output limit as a fraction of Pmax
nspin_capability_mwExplicit offline non-spinning capability
reg_up_offer_per_mw_hourRegulation-up reserve offer
reg_down_offer_per_mw_hourRegulation-down reserve offer
spin_offer_per_mw_hourSpinning-reserve offer
nspin_offer_per_mw_hourNon-spinning-reserve offer

Flag_UC remains the canonical commitment-required flag. A quick-start unit that provides offline NSPIN still needs commitment variables, so it must use Flag_UC = 1.

Initial operational state

Chronological operation requires state that cannot be inferred from static nameplate data:

  • initial_generator_state.csv provides commitment, generation, in-service status, and elapsed online/offline durations for every stable generator ID.
  • initial_storage_state.csv provides initial stored energy for every stable storage ID.

These files intentionally remain separate from gendata.csv and storagedata.csv: they describe the start of a simulation, not permanent asset properties.

For linked or restart workflows, files.operational_state_artifact may instead identify a versioned state directory relative to DataCase. It contains the same physical carry-over values plus timestamp, lineage, physical-system fingerprint, and integrity hashes. Do not configure it together with the two legacy CSV fields. Completed DART runs publish a reusable artifact at output/operational_state/. See Operational-State Contracts.

Native real-time series

A DART case may configure three native subhourly files:

dart_settings:
    files:
        real_time_load: load_timeseries_realtime_regional.csv
        real_time_wind: wind_timeseries_realtime_regional.csv
        real_time_solar: solar_timeseries_realtime_regional.csv

All three files must be supplied together. Each row must contain Month, Day, Hours, and Minute, followed by the regional columns used by the installed system. Hours follows HOPE's 1:24 convention. Minute must align with real_time_intervals_per_hour; for 12 intervals per hour it is 0, 5, 10, ..., 55.

The native files must have matching, unique, consecutive timestamps and cover the selected DA/RT horizon. Load factors must be finite and nonnegative. Wind and solar availability must lie in [0, 1]. Nonzero interchange belongs in dart_settings.interchange, not the regional NI column.

The hourly files continue to define the day-ahead forecast. Native real-time load replaces repeated hourly load, while native wind and solar values replace the corresponding real-time renewable availability. Conventional-unit availability remains governed by the installed system and configured outage.

If no native real-time files are configured, HOPE warns and falls back to repeated hourly values or the legacy inline multiplier pattern. If files are configured without Minute, HOPE warns and rejects them because their subhourly chronology cannot be verified.

Manifest and validation

The standalone format currently uses schema_version: 2. This version marks the merged static DART columns and native real-time file contract; it is not a scenario identifier. Scenario selection continues to come from the case/input folder chosen by the user.

Validate a case without solving or writing outputs:

using HOPE
validation = validate_hope("/path/to/case")

Validation verifies manifest hashes, stable IDs, the installed network, chronology, initial state, compatible settings, and enabled DART constraint families.
